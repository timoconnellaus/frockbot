# Research: DeepSeek Harness runtime lessons for FrockBot Durable Objects

## Summary

DeepSeek Harness is a plugin-composed Node host whose default Agent driver runs an evented turn/step loop against an append-only session log; optional persistence, checkpoint policy, API, and browser plugins surround that loop. FrockBot should copy its narrow capability seams, durable event vocabulary, model-request reconstruction, fail-closed checkpoints, conservative unknown-outcome recovery, and server-derived client projections—but not its process-resident loop ownership, asynchronous durability default, filesystem/SQLite backends, non-durable cancellation, mid-turn repair-only recovery, or separate headless product runtime.

## Findings

1. **Copy the small Agent contract and plugin-owned behavior (positive, high).** `packages/core/agent-loop/README.md` says the sole concrete driver implements the public `Agent` interface, registers a factory on `ctx.agents`, and confines the loop to “call the model, run the tools, repeat”; other behavior attaches through session and `agent/*` events. `docs/architecture.md` likewise makes model adapters, tools, session log, and loop replaceable plugins whose registrations unwind on unload. For FrockBot, keep the Bot Durable Object’s orchestration kernel provider-neutral and expose model, tool, persistence-policy, projection, and integration capabilities through narrow declared Contribution interfaces. Do **not** expose Cordis or provider types across the DO/API seam. [Agent-loop package](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md) (`packages/core/agent-loop/README.md`) · [Architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) (`docs/architecture.md`)

2. **Copy the event-log-as-request-source invariant (positive, critical).** `docs/architecture.md` defines durable `turn/*`, `step/*`, user, assistant, and tool events and states that the session log is the source of model context: anything model-visible must be reconstructable from it. That is directly compatible with a DO-owned log and FrockBot’s requirement to reconstruct every exact normalized model request. FrockBot should additionally persist the fully normalized provider-neutral request envelope (including route, prompt/tool-schema versions, and idempotency identity) before dispatch, rather than relying only on later derivation. [Architecture—Turn flow and Session log](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) (`docs/architecture.md`) · [Core subsystem](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/core.md) (`docs/subsystems/core.md`)

3. **Do not copy the default asynchronous admission-to-durability gap (risk, critical).** In `docs/subsystems/persistence.md`, `session/event` is synchronous only as notification: persistence copies events into a controller, batches them, and writes later. The separate checkpoint plugin flushes before model requests, before top-level tool bodies, and at step boundaries; its own README warns that a backend without this policy can lose events still in the batching window. This is weaker than FrockBot’s “admit input durably before acknowledging it.” A DO command handler must transactionally append admitted input/command and scheduling intent before replying, then use alarms/durable scheduling to continue. Batching is acceptable only after durable admission or for reconstructible presentation chunks. [Persistence—flush checkpoint](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/persistence.md) (`docs/subsystems/persistence.md`) · [Checkpoint policy](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session/session-checkpoint-policy/README.md) (`packages/session/session-checkpoint-policy/README.md`)

4. **Copy semantic side-effect barriers, but strengthen them with idempotency and reconciliation (positive with critical caveat).** `packages/session/session-checkpoint-policy/README.md` fail-closes model and top-level tool execution until prior intent is durable. It explicitly admits this is “durable execution intent, not exactly-once effects,” recommends forwarding `exec.callId` as an idempotency key, and records an unmatched side effect as unknown rather than retrying automatically. FrockBot should copy these barriers and conservative classification, while making every external effect record include an idempotency key or explicit reconciliation procedure before invocation. [Checkpoint policy](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session/session-checkpoint-policy/README.md) (`packages/session/session-checkpoint-policy/README.md`)

5. **Do not treat DeepSeek’s crash repair as sufficient DO recovery (risk, critical).** `docs/subsystems/persistence.md` preserves a cold log with an open turn, then appends synthetic recovery events and `turn/end { interrupted }`; the persistence README states that it does not resume execution in the middle of an interrupted turn. Tool recovery distinguishes not-started from outcome-unknown instead of blindly replaying. FrockBot should copy non-truncating repair and unknown-outcome handling, but persist an explicit execution state machine (admitted, request-intended, request-dispatched, response-recorded, tool-intended, tool-dispatched, reconciling, terminal) plus an alarm/resume cursor. Eviction must continue unfinished work, not merely close it as interrupted. [Persistence—crash recovery](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/persistence.md) (`docs/subsystems/persistence.md`) · [Persistence seam limitations](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/session/session-persistence/README.md) (`packages/session/session-persistence/README.md`)

6. **Do not copy process/fiber lifetime or default cancellation semantics (risk, critical).** `packages/core/agent-loop/README.md` says created-agent ownership belongs to the caller fiber and loop provider and that cancellation is cooperative; by default `agent.cancel()` clears pending inbox work. This is suitable for one Node process, not a DO contract where disconnect merely detaches an observer and cancellation must be explicit, authenticated, and durable. In FrockBot, neither WebSocket closure nor Contribution disposal may cancel a Turn; cancellation must append a command/event and survive eviction before the loop observes it. [Agent-loop creation, teardown, cancellation](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md) (`packages/core/agent-loop/README.md`)

7. **Copy backend authority and projection delivery; keep protocols narrow and versioned (positive, high).** The browser package map assigns browser↔host RPC/event delivery to `packages/client/connection`, while the host serves the page. `docs/api-gateway.md` separates validated unary Remote calls from session-event streams, pagination, projections, and entity substreams, even when they share one Connection. `docs/subsystems/session-projection.md` says host plugins fold durable events into whole current values and clients never fold domain events themselves. FrockBot should use authenticated command DTOs plus a resumable event/projection stream from the Bot DO, with the hosted UI as an observer and command submitter. Validate every inbound DTO and use stable sequence/watermark IDs for reconnect. [Client package map](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/README.md) (`packages/client/README.md`) · [API Gateway boundaries](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/api-gateway.md) (`docs/api-gateway.md`) · [Session projections](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/session-projection.md) (`docs/subsystems/session-projection.md`)

8. **Do not copy deployment-specific runtime multiplicity or storage providers (risk, high).** `docs/architecture.md` ships distinct `web`, `headless`, `sdk`, `sdk-minimal`, and `acp` profiles; `headless` is a one-shot runner with no server. Persistence providers are local JSONL/Zstandard artifacts or `node:sqlite`. FrockBot’s one-production-path rule instead requires browser, native shells, development, and tests to exercise the same DO protocol and Agent runtime. Reuse plugin composition ideas, but compile/validate backend Contributions for DO constraints and store canonical state in DO storage; do not introduce a local headless product Agent loop, runtime patch tree, local files, or SQLite as alternate authority. [Profiles and bundles](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md) (`docs/architecture.md`) · [Persistence backends](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/persistence.md) (`docs/subsystems/persistence.md`)

9. **Adopt DeepSeek’s recovery tests as a floor, not a ceiling (positive, medium).** `packages/core/agent-loop/tests/resume.spec.ts` tests restored history, continued turn numbering, non-duplicated sequence numbers, and pending injected context. FrockBot needs these plus DO-specific restart/eviction tests: durable input before response, alarm-driven continuation, duplicate command/model/tool delivery, cancellation across eviction, effect reconciliation, and client disconnect without cancellation. [Resume tests](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/tests/resume.spec.ts) (`packages/core/agent-loop/tests/resume.spec.ts`)

## Recommended FrockBot shape

- One Bot Durable Object owns command admission, the append-only event log, execution-state cursor, idempotency records, cancellation, alarms, and Agent-loop serialization.
- Backend Contributions register against provider-neutral interfaces; provider credentials and translations stay server-side inside provider plugins.
- Each transition that can lead to an external effect first commits intent and its idempotency/reconciliation metadata in DO storage.
- A reconnecting client requests events/projections after a sequence watermark; disconnect changes observer state only.
- Hosted WebUI and thin native shells use the same authenticated commands and stream protocol; test adapters target that same path.

## Gaps and residual risks

- The repository documents a Node host and local persistence, not Cloudflare Durable Object scheduling, transactional storage, alarm, hibernation, or WebSocket semantics; all DO mapping above is an architectural recommendation, not a claim about DeepSeek implementation.
- `master` URLs are mutable. Pin links to the reviewed upstream commit before relying on this brief for a long-lived ADR.
- The inspected sources do not establish durable, authenticated cancellation or durable input-before-acknowledgement; these remain mandatory FrockBot-specific designs and tests.

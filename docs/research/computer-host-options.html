Decision brief

A better home for the Computer

Fly Sprites gives FrockBot the right user experience, but not the per-Computer billing data we need. Seven current platforms were assessed against the product’s actual boundary: an isolated Linux desktop, durable files and browser identity, sleep/resume, controlled egress, and defensible prepaid billing.

Status · deferred 10 September 2026This brief preserves the research for a later Computer-host decision. Cloudflare Containers, GKE Agent Sandbox and the other replacement paths are outside the current payment implementation.

Recommendation

Prototype Cloudflare Containers and GKE Agent Sandbox before building a fixed Fly tariff.

Cloudflare remains the lead because it exposes per-instance billing usage and keeps FrockBot on its existing platform. GKE is now a serious challenger: Agent Sandbox is designed for isolated, stateful agent environments, and Pod snapshots can preserve memory plus filesystem state. Its snapshot suspend/resume path is newer and currently needs more cluster setup, so a small two-host bake-off is justified before committing.

Temporary option

Kubernetes path

GKE changes the shortlist

A generic Kubernetes cluster adds too much machinery. GKE Agent Sandbox is different because its API is specifically shaped around isolated, stateful, single-replica agent environments.

Why it is viableAutopilot bills requested Pod CPU and memory in one-second increments while Pods are creating or running. At current Iowa list rates, 1 vCPU + 6 GiB is about US$0.074/hour before persistent disk and shared cluster costs—almost identical to the Cloudflare estimate at 25% CPU. Agent Sandbox adds stable identity, persistent storage, default-deny networking, gVisor isolation and warm pools. Pod snapshots can capture memory and filesystem state, avoiding Cloudflare’s forced browser restart.
Why it does not lead yetThe full snapshot suspend/resume workflow requires a recent GKE version, Cloud Storage and IAM setup, and currently uses a temporary manual installation until snapshot support is fully available in the managed add-on. Customer attribution would also be FrockBot-owned lifecycle accounting or OpenCost, rather than a simple vendor feed like Cloudflare’s.

Persistence caveatCloudflare says all local disk is ephemeral. Object storage is not POSIX storage. Chromium must be stopped before checkpointing; crashes can lose work since the last completed backup. This must be measured in a prototype.

Recovered prior art

ZeroBSAI already tested the hybrid filesystem

The old implementation did not treat R2 FUSE as a normal local disk. It separated durable user files, high-churn local data, encrypted recovery snapshots and semantic memory.

R2 FUSE workspace

A per-user R2 prefix was mounted at /workspace with tigrisfs. This provided continuously durable ordinary files while the Cloudflare Container itself remained disposable.

Local POSIX escape hatch

Package directories stayed on local disk. The remembered C code intercepted mkdir/mkdirat and invoked a tightly scoped mount helper so node_modules was bind-mounted before its first write reached FUSE.

Restic recovery layer

High-churn caches and package state were snapshotted separately into encrypted restic repositories on R2 and restored after a cold start. A root-owned socket daemon kept R2 credentials away from ordinary sandbox commands.

R2 + Vectorize memory

Markdown was the durable source of truth in a separate R2 bucket. Vectorize stored replaceable chunk embeddings and metadata; pinned preferences plus top semantic matches were loaded before each model turn.

What to reuseKeep durable user files and agent memory outside the container. Keep Chromium’s profile, SQLite, LevelDB, package trees and build caches on fast local POSIX disk, then checkpoint them only from a quiesced state.
What to redesignThe C helper lives in the related crabby-kit implementation; ZeroBSAI retained a polling shell predecessor in a stash. The setuid helper and direct R2 credentials need a fresh security review before reuse, and neither approach makes FUSE suitable for a live Chromium profile.

Open questions

What the prototype must answer

Can Chromium’s profile be restored safely?
Cloudflare explicitly warns that object storage is not POSIX-compatible and that partially written files may be captured inconsistently. The safe sequence is to stop Chromium, verify profile locks are gone, create a directory backup, record its handle durably, then stop the container. The restored copy-on-write overlay is also ephemeral, so restoration must run on every wake. A direct live R2 FUSE mount should be limited to ordinary workspace files unless tests prove otherwise.
Does the hybrid filesystem remain predictable?
ZeroBSAI proved that ordinary files can live on an R2 FUSE mount while package state stays on local POSIX disk. The prototype must test permissions, deletion, concurrent writes, cross-layer moves and cold recovery. Chromium’s profile remains local and is captured only after a clean shutdown.
Can memory stay independent of the Computer?
Canonical Markdown memory should remain in R2 and be available when the Computer is asleep. Vectorize is a rebuildable retrieval index, not the source of truth. The prototype should prove both graceful fallback and a full index rebuild from R2.
Does the usage feed arrive quickly enough?
The billing dataset has the right per-instance dimensions and units, but the reviewed documentation does not promise freshness. FrockBot can reserve the worst-case cost for a bounded awake window and settle later; the prototype should measure query lag under real workloads.
Do we need process continuity?
Most Computer operations can resume from durable turn intent plus files. Long-lived background services would restart after sleep. If preserving RAM and running processes is a hard product requirement, Daytona VM pause—or continuing with Sprites—fits better.
What happens to inactive accounts?
Cloudflare backup handles default to a three-day TTL, enforced when restoring, while expired R2 objects remain until separately deleted. FrockBot must set a longer explicit TTL, own R2 lifecycle cleanup and define an account-deletion path before real users arrive.

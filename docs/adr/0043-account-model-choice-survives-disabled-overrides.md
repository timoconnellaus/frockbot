# Account model choice belongs to the User, with a bounded previous-reader projection

Account model choice is required base behavior on Models; the optional Custom models Package owns only Bot overrides. Keeping the account choice in that Package made disabling overrides also disable the account default. The User Durable Object now stores one versioned account-model record alongside its existing settings record, committing both and the configuration receipt atomically. The forward migration promotes only an active old account choice, removes the old Package field and preserves inert Bot overrides.

An additive key keeps the previous released settings DTO readable during rolling deployment. Previous RPC readers receive their exact DTO shape, with its fallback slot projecting the valid effective account choice; current readers explicitly request view 2 and see account and platform defaults separately. This bounded wire projection does not restore the removed Package control. Old client writes to that control receive an update response before admission. The first write preserves a recovery checkpoint, and injected transaction failure proves the settings seam rolls back together. This does not claim full generation activation or storage-revert qualification.

Choosing a model provider on Models is the constitution's explicit provider opt-in. The User owner installs its manifest dependency closure in one command; generic Package lifecycle controls remain on Plugins. Provider credentials stay on the backend Models authorization surface, reached from native by an expiring same-User browser handoff. Both renderers use the same manifest-derived field homes, owner-bound commands, receipts and revision checks.

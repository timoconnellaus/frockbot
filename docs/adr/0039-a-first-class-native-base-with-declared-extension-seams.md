# A first-class native base with declared extension seams

Tim accepted this direction on 2026-09-05 and explicitly instructed the constitution amendment before implementation. This ADR records that amendment; phase 1 delivers contracts and a plan, not a native application or a claim that the later runtime guarantees are already implemented. The supplied external review contains sections 03–05 and part of 06, ending at “In a separate backend”; section 07 was not present. The owner's brief supplies the remaining delivery scope.

FrockBot will have a minimal durable kernel, an ordinary reviewed product base, and runtime Packages at declared seams. Flutter is the primary native renderer. A2UI describes extension UI through a compiled, reviewed FrockBot catalog; existing Applets and the Computer viewer retain an isolated web fallback. Browser and native clients submit the same commands and read the same projections. Neither owns Agent execution or business rules.

## Constitutional amendments and their reasons

| Previous rule                                                                 | Replacement principle                                                                                                                                | Why                                                                                                                             |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| Every parity capability and all non-kernel production code are Packages       | Parity is an outcome; reviewed base behavior sits beside the minimal kernel; runtime extensions use declared narrow seams                            | Fixed navigation, projection and account policy need explicit construction, not install/repair lifecycles                       |
| Hosted WebUI is the product; native clients are thin shells                   | First-class native and browser renderers share backend commands, projections and execution semantics                                                 | Native editing and navigation require a renderer boundary, not another Agent runtime                                            |
| Required safety surfaces are mandatory first-party Composition members        | Compile non-disableable conversation, auth, settings, recovery, audit, undo, authoring entry points, deny-only guards and trust chrome into the base | A failed or hostile extension must not remove or impersonate the exit or the trust label                                        |
| A Bot may change anything above the kernel                                    | A Bot changes declared extension points and permitted configuration, never base code, trust chrome, the kernel, constitution or grants               | The reviewed base is an enforceable boundary                                                                                    |
| Every Package receives the full Bot account grant                             | Account-wide availability remains; each Package receives an inspectable allowed subset                                                               | Least privilege need not restore per-Bot Assignments or repeat consent; self-authored declarations cannot grant themselves more |
| Forward migrations coexist with unconditional code revert                     | Runnable generations declare a storage-schema window; activation and revert cross a guarded migration boundary                                       | Old code must not mount over incompatible data; code undo is not data undo                                                      |
| An in-flight Composition is pinned while access can be revoked                | Pin implementation/schema history; check live authorization before new external effects, even in-flight                                              | Revocation wins over a cached binding; already-dispatched work remains subject to reconciliation                                |
| Stored shapes migrate forward and no backward behavior is honored             | Keep forward-only storage migrations and separately bound supported wire/catalog versions and minimum native version                                 | Installed clients update independently; compatibility does not restore removed features                                         |
| Shell technology, hosting and workflow commands are constitutional mechanisms | Keep their guarantees here; describe mechanisms in architecture docs and rollout gates in plans                                                      | A tooling replacement must not look like an authority amendment                                                                 |

The account grant remains User-owned and uniform across Bots. Binding policy computes the intersection of enabled capabilities, reviewed allowance, and declared need; changing a manifest cannot widen the allowance. Live authorization applies transitively through tools and Connection leases, not only at initial isolate construction. Revocation records an authorization epoch and explicit effect refusal. A dispatched effect may already have happened; fencing prevents its next use and never invents rollback.

A generation declares readable and writable schema ranges. Promotion checks both the retained generation set and active calls, drains or fences incompatible work, checkpoints recoverable state, and validates migration and health before committing the new generation. Expand/contract is the default: destructive contraction waits until no runnable or pinned generation requires the old shape. A failed check preserves the prior runnable data. An incompatible revert returns a visible repairable refusal; a compatible revert records a new generation and does not set last known-good merely by moving a pointer. The implementation and recovery proofs are prerequisites in the native plan.

## Guarantees retained

Cloud and Durable Object authority; durable admission before acknowledgement; explicit authenticated cancellation; resumable execution after observer loss or eviction; intent before effects and explicit reconciliation; immutable artifacts and writer provenance; isolation of untrusted code with no ambient network or secrets; Memory and Skills without waking the Computer; one home per setting and Connection; and visible failure, recovery, audit and undo all remain invariants. The kernel still imports no Package and contains no product policy. Account-shaped enablement, zero-configuration operation, quotas, quarantines, hosted workflow parity, and the User's control of publication remain.

## Alternatives and consequences

Retaining a full WebView would preserve one renderer but would not deliver the accepted native interaction model. Making the entire app a remote A2UI document would make permanent trust chrome dependent on extension processing. Making the base another giant controller would remove manifests without reducing coupling. Instead, small public contracts separate ConversationReadModel, ExtensionRuntime and UserRecoveryScheduler; their implementation is staged, not smuggled into this amendment.

A2UI and GenUI are qualified independently of Compose. GenUI supplies rendering pieces behind one FrockBot adapter, never a local model or conversation loop. `@frockbot/compose-*` remains a separate vendoring effort. Compose adoption must close redirect credential forwarding and default-host hazards before loading a real extension.

This supersedes packaging and native-shell requirements in ADRs 0001, 0005, 0007, 0008 (direct hosted mobile and User publication), 0011, 0020, 0021 and 0022 only to the extent stated above. It narrows Package authority and revocation timing in ADRs 0019, 0020 and 0008 (credential generations). It replaces the “client and Worker ship together” compatibility assumption in ADRs 0026 and 0028. Their durable owners, effect records and provenance remain. Earlier ADRs stay as decision history.

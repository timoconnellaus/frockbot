## Implemented flow

The Dart app persists PKCE verifier/state before opening the system browser. The gateway reuses Better Auth's existing Google web OAuth client (`757079918011-jnhcm9etic2v7rpc8vq33kffmvo6j38h.apps.googleusercontent.com`), then redirects to an exact associated HTTPS return path. The User Durable Object records one-use exchange and seven-day session issuance before the native bearer is returned. Native requests carry a matching, session-bound protocol/version/catalog hello. The protected store retains credentials and command recovery records; logout revokes the backend session. Warm/cold callback, state mismatch, replay, redirect and expiry logic have automated coverage; actual OS/browser return is unverified.

Bot selection, cached local directory, paged conversation, native text composer, explicit Stop and recovery use the existing backend routes. Stable send/Stop ids are persisted before dispatch. An uncertain send is looked up and, if absent, fenced before a new send can be admitted. State-channel cursors are persisted only after the corresponding projection is applied. Closing or suspending a client detaches the observer.

The deterministic form has a bounded compiled widget catalog, field validation, a User-owned save receipt and duplicate-save reconciliation. Hostile trees fail inside the form region. It remains a fixed qualification fixture, **not a Package-owned A2UI action implementation**. Revoked Package actions, all protocol features, update floods/media budgets and qualified catalog negotiation are unfinished.

The fallback uses `webview_flutter`, an anonymous reviewed bootstrap, an exact sandboxed child-frame handshake and navigation epochs. The app session never enters that context. Two-minute User/Applet/generation viewer access is sent after handshake and carried in the WebSocket subprotocol, outside URLs/history. The host confirms external links before opening the system browser. Existing Applet artifacts need rebuilding with the new SDK handshake. Physical cookie/token/network/bridge isolation, expired/open-socket behavior, old-view token fencing and a real published Applet mutation/reconnect remain unproven.

`NATIVE_SLICE_2_AUTH` is absent from production configuration. It can select Android qualification, or Android plus macOS once the signing gate passes. Well-known return associations and auth/bootstrap routes must be deployed to the real origins before device acceptance. The live Android association URL returned HTTP 401 on 2026-09-05, confirming that verified native sign-in is not ready at the hosted origin. This PR does not deploy those routes.

FrockBot / Accepted direction · 5 September 2026

A native base.
Extensions at declared seams.

Phase 1 defines the constitution, shared wire contracts and delivery gates. Flutter owns native interaction. The Bot Durable Object continues to own execution. The Flutter application is the next slice.

Durable kernel

One authority

Admission, events, cursor, cancellation, scheduling and immutable generation activation stay in their Durable Objects.

Reviewed base

Permanent product behavior

Flutter and browser renderers share commands and projections. Auth, chat, settings, recovery, audit and trust chrome remain host-owned.

Runtime extensions

Bounded and inspectable

A2UI uses a compiled catalog. Applets and the Computer viewer use an isolated web fallback. Bindings expose only the allowed capability subset.

The constitutional change

Previous rule Accepted replacement
Every capability beyond the kernel is a Package Minimal kernel, reviewed base, Packages at narrow extension seams
Native clients wrap the hosted WebUI First-class native and browser renderers over the same backend
Required core is a repaired Package set Required core is compiled into the non-disableable base
A Bot changes anything above the kernel Only declared extensions and permitted configuration; no base, chrome or grant changes
Every Package receives the full Bot grant An inspectable allowed subset, uniform across the User’s Bots
Code revert without a data compatibility boundary Runnable schema windows, guarded migration, visible incompatible-revert refusal
Pinned Composition can retain revoked access Pin implementation history; check live authorization before each new external effect
Client compatibility follows stored migrations Forward-only storage plus a bounded wire/catalog window and minimum native version
Shell, hosting and workflow tooling are constitutional Mechanisms live in architecture docs; temporary rollout gates live in the plan

Guarantees retained: cloud authority, durable admission, authenticated Stop, resumability, effect intent and reconciliation, immutable artifacts and provenance, untrusted-code isolation, Computer-independent Memory/Skills, one settings home, visible recovery and undo.

Six useful stopping points

0 · Repair and prove existing invariants

Exit: failed activation preserves data; publication cannot alter a pinned call; revocation fences the next effect. Proof: facet health/migration failures, concurrent calls, restart and bounded history regressions.

1 · Amend the constitution and define contracts

This phase: one JSON Schema source, TypeScript and Dart generated output, shared valid/invalid fixtures, compatibility refusal and the plan. Proof: generation freshness, existing-decoder conformance, gateway refusal before loading, typecheck, formatting and architecture checks.

2 · Prove one native vertical slice on Pixel and desktop

Exit: the complete auth/chat/A2UI/Applet flow works with the exact pins, measured budgets and isolation. Proof: real-device interaction, same-signer upgrade, hostile WebView inspection, duplicate actions, suspension and DO eviction.

3 · Deliver the native base alongside Vue

Exit: trusted settings, recovery, audit/undo, extension management, voice/files and notifications have workflow parity. Proof: paired renderer scenarios against one backend; signed updates and the lowest supported device.

4 · Qualify A2UI and Compose independently

Exit: catalog/action admission is bounded and reconstructable. Compose passes one real-extension proof behind its own adapter. Proof: synthetic-credential redirects, omitted-host refusal, live grants, immutable snapshots and recovery. A wholesale Compose rewrite does not block Flutter.

5 · Make explicit retirement decisions

Exit: replace Capacitor/Electron only after parity and upgrade evidence. Decide Flutter Web separately. Proof: previous-client upgrade, minimum-version response and continued Applet/Computer fallback.

Gates that remain open

Technology: the exact protocol/library/catalog combination needs device qualification. Backend: failed-activation data protection and live authorization need recorded regression evidence. Distribution: Apple 4.7 may require product changes; A2UI is not an exemption. Windows/Linux remain deferred.

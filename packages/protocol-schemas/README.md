# Client wire schemas

`schema/client-wire.schema.json` is the **one language-neutral source** for the native client contract. It is a JSON Schema 2020-12 bundle: select a named `$defs` entry, rather than validating against the permissive bundle root. `x-frockbot-compatibility` is a policy annotation, from which both languages' constants are generated. No DTO, schema, header or catalog assertion grants authority.

These contracts started in phase 1. Slice 2 adds a gated Flutter/auth/fallback qualification prototype; its unmeasured device gates are recorded in `docs/plans/native-acceptance-2026-09-05.md`. The production A2UI action router and unified settings read model remain planned. Existing production decoders remain in place. Generated Dart classes validate and round-trip JSON, expose typed object fields and scalar values, and detach mutable input/collections. JSON unions retain their discriminator in toJson(); presentation models belong to the consuming native slice.

## Generation and checks

Run from the repository root:

```sh
bun run generate:protocol
bun scripts/check-client-protocol.ts
bun test packages/protocol-schemas apps/cloudflare/src/client-protocol-conformance.test.ts
dart apps/native/test/protocol_fixtures.dart
```

`bun scripts/generate-dart-protocol.ts` writes `apps/native/lib/protocol/client_wire.generated.dart`. It needs Bun, not Dart. The fixture runner needs Dart; phase 1 was also run with the local Flutter SDK's Dart 3.13.0 binary. Both runners read the same `fixtures/valid.json` and `fixtures/invalid.json`. Neither duplicates fixture data. Every named schema has at least one valid and invalid fixture.

TypeScript declarations and predicates are generated from that same schema. Ajv 8.18.0 compiles JSON Schema 2020-12 at build time; esbuild bundles its standalone predicates, with no runtime schema compilation or dependency in a Worker. The Dart generator supports exactly the schema keywords used in the bundle and refuses unfamiliar keywords before emitting output. Its generated evaluator is not a general JSON Schema implementation. Growing that dialect requires cross-language positive and negative fixtures. Both adapters must enforce the transport depth limits below before schema evaluation.

`types.generated.ts`, `validators.generated.js`, `validators.generated.d.ts`, and `compatibility.generated.ts` are committed generated output. The minified standalone JavaScript is excluded from Prettier because regeneration is its format check. Both generators support `--check`, run by the repository typecheck command.

The conformance test maps every fixture for the existing named seams to their production decoders, checking both acceptance and rejection. This is fixture conformance, **not a proof of complete decoder equivalence**. No handwritten decoder was replaced. The schema is a selected wire window: existing stored migrations and wider legacy/local-development shapes are not a second schema source and are not automatically accepted by native clients.

## Admission, observation and recovery contract

A User/Bot owner authenticates the route identity and decodes before recording a command. Persist a cryptographically random command id locally **before** sending; retries retain the exact id and body. The owner fingerprints the normalized body, admits durably, records a receipt and replays that receipt for duplicates; a changed body under an old id is a refusal. Accepted means durable intent, not completed execution. The planned generic receipt and new-conversation lookup must use this existing admission machinery before native consumes them.

Stop targets a run and has its own command id. Its accepted receipt may still project `running`; cancellation becomes terminal only through the Bot's durable fence and reconciliation. Network loss, backgrounding, a stream ending, and WebView disposal are never Stop. On an uncertain send, lookup by the retained id and use the existing admission-fence/reconciliation protocol; never mint a replacement id merely because a request timed out.

Observer frames carry no transcript. Persist or retain the last applied observer cursor as a cache, reconnect after it, and re-read HTTP projections on invalidation or reset. A reset for gap/cursor-ahead discards observer assumptions. Read pages independently of transcript rendering, preserve scroll anchors, and never hydrate exact model requests just to show recent messages. Announcements and structured sends preserve durable identity; plain assistant text is not an extra user-visible send.

## Compatibility window

Initial supported protocol interval is **[1, 1]** and minimum native semantic version is **1.1.0**, chosen for the first Flutter build after the Capacitor application's `1.0`. These are generated constants, not client-selected policy. Header values are bounded to 4,096 characters and exact fields. Missing negotiation on reserved native/auth routes, malformed versions, and old/new unsupported protocol versions receive HTTP 426, `Cache-Control: no-store`, and `Update the app to continue using FrockBot.` before auth dispatch or application loading.

Unversioned existing browser/Capacitor traffic remains supported during rollout. The header is compatibility metadata, not proof that a caller is native; removing it cannot bypass authentication, ownership or effect authorization. Every new native request must include it, including socket upgrades. The phase-2 native session adapter binds the negotiated version to the session so omission cannot select a different window. Existing Applet viewer sockets remain on their independent scoped-token protocol.

No A2UI catalog is advertised until qualification. A client may present catalog pairs the server does not know and still use core workflows; a surface renders only on an exact negotiated protocol/catalog id/digest match. Otherwise the host shows unavailable or the separately approved web fallback. On first qualification, advertise one compiled catalog; thereafter retain at most current and previous wire/catalog generations, with a 90-day migration window. A security removal may close the window earlier with an update response. New fields go in a new version when an exact-key decoder would refuse them. Removed product behavior is not reinstated for a slow client. Minimum-version increases require a reachable signed update for every supported distribution target.

## Validation beyond object shape

JSON Schema checks structural shape, cardinality, numbers, string code-point lengths, literals and allowed fields. It does not authenticate a User, verify a digest against bytes, prove a timestamp is a real instant, or compare two referenced durable records. Existing endpoint decoders continue enforcing UTF-8 byte bounds, real timestamps/cursors, Run/Stop receipt identity and catalog-specific rules. New adapters must do the same before these DTOs become production surfaces; passing a schema is never sufficient admission.

Apply bounded reads before JSON parsing: 512,000 bytes per conversation page, 256,000 per turn response, 32,000 UTF-8 bytes of Turn input, 4,096 per state frame, and 262,144 per extension document. Limit JSON nesting to 16; reject cycles before rendering. A2UI has tighter renderer budgets in the native plan. Preserve source bytes and validated surface snapshots by hash for reconstruction. Action required-field names must exist in their declared property map; numeric minimum must not exceed maximum; action ids must be unique. No remote schema refs, unknown functions or native bridge names are accepted.

Before an A2UI action, authenticate ownership; resolve the exact Package/generation/surface revision; validate the declared action input; check enablement and the live allowed capability subset; durably admit its command id; and record a known result or reconciliation state. Cross-User, stale, disabled, revoked and mismatched-artifact actions fail visibly. There is no generic “call any tool” action. The action DTO carries no grant, Connection credential, native API operation or client-chosen owner.

Only the first-party native auth adapter sees AuthSessionView.sessionToken, kept in OS-protected storage. It never reaches an A2UI document, Applet, catalog, log or Computer. SettingsFrame is a backend-produced redacted view; Package field declarations cannot become credential editors or trust labels. The host checks the owning configuration surface and presents sensitive controls itself.
